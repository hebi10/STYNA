# STYNA 쇼핑 우선 하이브리드 UI 개선 설계

## 1. 목적

STYNA를 실제 쇼핑몰처럼 빠르게 탐색하고 구매 흐름을 체험할 수 있는 포트폴리오로 정리한다. 홈과 내비게이션은 쇼핑을 우선하고, 포트폴리오 설명은 홈 하단 한 구역과 기존 쇼핑 가이드로 통합한다. 기존 Firebase 데이터 모델, 권한 정책, 로그인 방식과 주요 기능은 보존한다.

이번 설계는 2026-07-27 Impeccable 전체 비평의 `25/40` 기준점을 사용한다. 우선순위는 데이터·구매 흐름의 P1 결함, 상태 처리, 정보 구조, 모바일 대응, 보조 화면 일관성, 접근성·성능 순서다.

## 2. 고정 제약

- 이메일·비밀번호 로그인, 일반 회원 빠른 로그인, 관리자 빠른 로그인을 모두 유지한다.
- 빠른 로그인은 `NEXT_PUBLIC_ENABLE_DEMO_LOGIN=true`인 포트폴리오 데모 배포에서만 노출한다.
- 일반 회원과 관리자 빠른 로그인은 기존 계정 역할과 redirect 정책을 유지한다.
- 관리자 권한 판정과 서버·Firebase 권한 정책을 완화하지 않는다.
- Firebase 문서 구조, Firestore Rules, Storage Rules와 기존 공개 URL을 변경하지 않는다.
- 새 쇼핑 기능, 결제·배송 정책, 데이터 마이그레이션을 추가하지 않는다.
- 기존 Pretendard, 흑백·오프화이트, 얇은 구분선과 4열/2열 상품 매대 문법을 유지한다.
- 새 `box-shadow`와 `border-radius`를 추가하지 않는다.
- 기존 기능·카피의 사실 관계를 보존하며, 포트폴리오 데모임을 숨기지 않는다.
- 사용자가 별도로 요청하지 않으면 커밋·푸시·배포하지 않는다.

## 3. 목표 경험

### 3.1 첫 방문

사용자는 첫 화면에서 상품·카테고리·추천을 쇼핑몰의 순서로 인식한다. 포트폴리오 구현 설명은 상품 탐색을 방해하지 않으며, 홈 하단과 쇼핑 가이드에서 필요할 때 확인할 수 있다.

### 3.2 상품 탐색

홈, 전체 상품, 검색과 추천은 같은 공개 상품 상태 의미를 사용한다. 로딩·오류·실제 0건이 서로 다른 화면과 행동을 제공하며, 권한 또는 네트워크 실패가 빈 상품 목록으로 표현되지 않는다.

### 3.3 구매 진입

비로그인 사용자가 장바구니에 진입하면 로그인 필요 이유와 다음 행동을 바로 확인한다. 로그인 완료 후 원래 장바구니로 복귀하고, 쇼핑을 계속하려는 사용자는 상품 목록으로 돌아갈 수 있다.

### 3.4 포트폴리오 검토

검토자는 환경변수가 활성화된 배포에서 일반 회원과 관리자 계정을 빠르게 체험할 수 있다. 두 역할의 진입점은 명확하지만 실제 권한 정책을 우회하지 않는다.

## 4. 정보 구조

### 4.1 헤더

현재 목적지를 다음 다섯 그룹으로 재구성한다.

1. `SHOP`
   - 전체 상품
   - 카테고리
   - 신상
   - 베스트
   - 세일
   - 브랜드
2. `추천`
3. `이벤트`
4. `리뷰`
5. `고객지원`
   - FAQ
   - 1:1 문의
   - 상품 문의

검색, 장바구니, 로그인·마이페이지와 관리자 진입은 별도의 사용자 메뉴로 유지한다. 데스크톱에서는 그룹형 내비게이션, 모바일에서는 같은 데이터로 렌더링되는 disclosure 그룹을 사용한다. 모바일 메뉴의 dialog, Escape 닫기, 포커스 순환과 닫은 뒤 트리거 복귀 동작은 유지한다.

### 4.2 홈

홈은 다음 순서로 구성한다.

1. 메인 배너
2. 주요 카테고리
3. 에디터 추천 상품
4. 신상품
5. 베스트 랭킹
6. 세일 상품과 이벤트 연결
7. 배송·교환·혜택 안내
8. 포트폴리오 데모 안내

현재 별도로 존재하는 스타일 조합 안내, 상품 데이터 설명, 데모 리뷰, 혜택 안내 예시와 반복 `PORTFOLIO DEMO` 문구는 마지막 포트폴리오 안내 구역으로 통합한다. 스타일 조합 카피는 독립 섹션으로 유지하지 않고 에디터 추천 상품의 큐레이션 설명에 흡수한다.

포트폴리오 안내 구역은 다음 정보만 제공한다.

- 실제 결제가 진행되지 않는 데모라는 사실
- 일반 회원·관리자 역할을 체험할 수 있다는 사실
- 구현된 상품·주문·리뷰·이벤트·관리 기능의 범위
- 상세 설명을 여는 쇼핑 가이드 진입점

### 4.3 보조 화면

인증, 마이페이지와 관리자 화면은 공개 쇼핑 화면의 토큰·타이포그래피·상태 표현을 기준으로 맞춘다. 그라데이션 텍스트, 목적 없는 측면 강조선, bounce easing과 과도한 장식은 실제 화면을 확인한 뒤 축소한다. Impeccable detector의 장식 경고는 자동 수정 목록이 아니라 검토 후보로만 사용한다.

## 5. 데이터와 상태 설계

### 5.1 공개 상품 조회

홈 추천, 상품 목록과 검색은 기존 공용 query key와 상품 서비스 계약을 유지하면서 다음 상태를 명확히 구분한다.

- `loading`: 이전 성공 데이터를 사용할 수 없으면 skeleton 또는 `role="status"` 상태를 표시한다.
- `error`: 사용자용 오류 설명, 재시도와 안전한 탐색 경로를 표시한다.
- `empty`: 조회는 성공했지만 상품이 없음을 알리고 적용된 필터 초기화 또는 전체 상품 이동을 제공한다.
- `success`: 조회 결과와 그 결과에 맞는 상품 수를 표시한다.

서비스 오류를 빈 배열로 변환하지 않는다. 상품 수를 알 수 없는 cursor 결과를 전체 상품 수로 표현하지 않는다.

### 5.2 홈 추천 실패

추천 설정 조회가 실패해도 홈 전체는 유지한다. 공개 상품 조회가 성공했다면 기존 추천 규칙에 따른 대체 매대를 표시하고, 대체 매대도 구성할 수 없을 때만 재시도 가능한 오류 상태를 표시한다. 반복 재시도로 해결되지 않는 권한 오류는 동일 요청을 무한 반복하지 않는다.

### 5.3 장바구니 인증 gate

인증 확인 중과 비로그인 상태를 분리한다.

- 인증 확인 중: `role="status"`와 진행 문구
- 비로그인: 제목, 로그인 필요 이유, `로그인하고 계속하기`, `쇼핑 계속하기`
- 로그인 링크: `/auth/login?redirect=/orders/cart`
- 로그인 완료: `getSafeRedirectTarget` 검증 후 `/orders/cart` 복귀

### 5.4 로그인

로그인 화면은 다음 네 영역을 유지한다.

1. 이메일·비밀번호 폼
2. 로그인 상태 유지와 비밀번호 찾기
3. 환경변수로 제어되는 포트폴리오 데모 로그인
4. 회원가입 진입

`NEXT_PUBLIC_ENABLE_DEMO_LOGIN === "true"`일 때 일반 회원·관리자 빠른 로그인을 표시한다. 환경변수가 없거나 다른 값이면 빠른 로그인 영역 전체를 렌더링하지 않는다. 로그인 오류는 `role="alert"`로 알리고, 전환 중에는 기존 `role="status"`와 redirect 동작을 유지한다.

## 6. 반응형과 고정 UI

- 기준 뷰포트는 `390×844`, `768×1024`, `1440×900`이다.
- 주요 버튼, 메뉴, 필터와 페이지 이동 요소는 최소 `44×44px`의 조작 영역을 제공한다.
- 모바일 상품 필터가 열렸을 때 챗봇이 적용 버튼과 필터 컨트롤을 가리지 않는다.
- 주문·인증 화면에서는 챗봇을 표시하지 않는다.
- 상품 상세에서 고정 구매 CTA와 챗봇이 동시에 같은 하단 영역을 점유하지 않는다.
- 고정 요소는 `env(safe-area-inset-*)`를 반영한다.
- 모든 지원 화면에서 문서 전체 가로 overflow가 없어야 한다.

챗봇의 기능과 대화 흐름은 변경하지 않는다. 수정 범위는 경로·상태에 따른 노출과 위치 충돌 방지다.

## 7. 디자인 시스템

### 7.1 기준

공개 상품 목록과 상세를 시각 기준으로 사용한다.

- Pretendard 중심의 명확한 크기·굵기 위계
- 검정 CTA, 밝은 표면, 얇은 구분선
- 버건디는 할인·이벤트 같은 의미 있는 강조에만 사용
- 4열 데스크톱·2열 모바일 상품 매대
- 이미지 위 장식보다 상품 정보와 큐레이션 카피를 우선

### 7.2 공통 패턴

기존 `Button`, `Input`, `PageHeader`, `ProductCard`를 우선 재사용한다. 다음 역할은 반복 구현하지 않고 공통 패턴으로 정리한다.

- 로딩·오류·빈 결과·권한 제한 상태
- 재시도·필터 초기화·로그인 이동 CTA
- 포트폴리오 데모 안내
- 헤더 내비게이션 데이터
- 비동기 상태의 `alert`·`status` 의미

공통화는 실제로 두 곳 이상에서 같은 역할을 사용할 때만 적용하며, 한 화면을 위한 추상화는 만들지 않는다.

## 8. 접근성·성능·카피

### 8.1 접근성

- 비동기 오류는 `role="alert"`, 로딩과 진행은 `role="status"`를 사용한다.
- 모든 아이콘 버튼은 접근 가능한 이름을 가진다.
- 키보드만으로 헤더, 모바일 메뉴, 상품 필터, 로그인과 장바구니 gate를 사용할 수 있어야 한다.
- dialog·disclosure의 `aria-expanded`, `aria-controls`, 포커스 복귀를 유지한다.
- 색상만으로 상태를 구분하지 않는다.

### 8.2 성능

- 메인 배너의 현재 활성 LCP 후보 한 장만 우선 로드한다.
- 비활성 배너와 아래쪽 이미지는 불필요하게 우선 로드하지 않는다.
- `transition: width`는 실제 시각 결과를 보존하면서 `transform`·`opacity` 또는 애니메이션 제거로 대체할 수 있는지 검토한다.
- 이미지 크기와 비율을 유지해 layout shift를 방지한다.

### 8.3 카피

- 사용자에게 보이는 `isNew`, `Bags`와 반복되는 `PORTFOLIO DEMO`를 한국어 쇼핑 문맥으로 정리한다.
- 코드·데이터 필드명인 `isNew`는 변경하지 않는다.
- 데모·정책 설명은 사실 관계를 유지한다.
- 실패 문구는 문제, 영향, 사용자가 할 수 있는 다음 행동 순서로 작성한다.

## 9. Impeccable 적용 순서

1. `$impeccable harden`: 상품 조회, 권한, 오류·빈 상태
2. `$impeccable clarify`: 장바구니와 로그인 복구 안내
3. `$impeccable distill`: 헤더와 홈 정보 구조
4. `$impeccable adapt`: 모바일 고정 UI와 터치 영역
5. `$impeccable audit`: 접근성·성능·반응형 기술 검사
6. `$impeccable polish`: 전체 경로 시각 일관성 마감

각 단계는 독립적인 테스트와 실제 화면 검증을 통과한 뒤 다음 단계로 넘어간다. detector는 UI 수정이 모두 끝난 뒤 한 번 실행하고, 최종 비평을 다시 실행해 `25/40` 기준점과 비교한다.

## 10. 검증과 완료 기준

### 10.1 자동 검증

- 로그인 환경변수 on/off와 세 로그인 경로 테스트
- 홈 추천 성공·권한 오류·대체 매대 테스트
- 상품 목록 loading·error·empty·success 테스트
- 장바구니 auth loading·비로그인·로그인 복귀 테스트
- 헤더 desktop/mobile 목적지와 접근성 상태 테스트
- 챗봇 경로·필터 상태별 노출 테스트
- 이벤트·로그인 오류의 alert semantics 테스트
- 메인 배너 LCP 우선순위 테스트
- 관련 Jest 테스트, `npm run typecheck`, `npm run lint -- --max-warnings=0`, `npm run build` 통과

### 10.2 브라우저 검증

- `390×844`, `768×1024`, `1440×900`
- 홈, 상품 목록, 검색, 실제 상품 상세, 이벤트, 로그인, 장바구니, 마이페이지, 관리자
- 일반 회원과 관리자 빠른 로그인
- 키보드 포커스와 메뉴·filter disclosure
- loading·error·empty·permission 상태
- 고정 챗봇·구매 CTA·필터 충돌
- 가로 overflow, 한글 깨짐, 콘솔 오류와 LCP 경고

### 10.3 완료 조건

- 이메일·비밀번호, 일반 회원, 관리자 로그인이 기존 권한으로 동작한다.
- 데모 로그인은 환경변수가 활성화된 배포에서만 노출된다.
- 홈·상품·검색의 데이터 상태 의미가 일치한다.
- 비로그인 장바구니에서 로그인과 쇼핑 복귀가 가능하다.
- 로그인 후 안전하게 원래 장바구니로 돌아온다.
- 홈의 포트폴리오 설명이 하단 한 구역과 쇼핑 가이드로 통합된다.
- 헤더와 모바일 메뉴가 동일한 다섯 그룹을 사용한다.
- 주요 터치 영역이 44px 이상이며 고정 UI 충돌이 없다.
- 지속되는 Firebase 권한 오류와 LCP 경고가 없다.
- Impeccable detector의 실제 결함이 해결되고 오탐은 수정하지 않는다.
- 최종 Impeccable 비평 결과와 남은 P0·P1 항목을 문서화한다.
