# 1:1 문의 실시간 알림 설계

## 1. 목표

- 고객이 1:1 문의를 등록하면 관리자 헤더에 읽지 않은 문의 알림을 즉시 표시한다.
- 관리자가 답변을 등록하거나 수정하면 문의 작성자 헤더에 읽지 않은 답변 알림을 즉시 표시한다.
- 알림이 있을 때만 헤더에 종 아이콘을 표시하고, 클릭하면 해당 문의 화면으로 이동한다.
- 문의 화면이 정상적으로 로드된 뒤 현재 사용자의 알림을 읽음 처리한다.
- 현재 분리된 `inquiries`와 `qna` 사용자 흐름을 정리해 1:1 문의와 상품 QnA의 책임을 명확히 나눈다.

## 2. 범위

### 포함

- `inquiries` 문서 기반 관리자·고객 읽음 상태
- Firestore 실시간 구독을 사용한 종 아이콘 노출
- 데스크톱·모바일 헤더 종 아이콘
- 관리자 신규 문의 확인 흐름
- 고객 신규 답변 확인 흐름
- 마이페이지 문의 링크와 1:1 문의 화면의 단일화
- Firestore 권한 규칙, 인덱스, 단위 테스트, 규칙 테스트, 브라우저 흐름 검증

### 제외

- 알림 목록 팝오버 또는 별도 알림 센터
- 알림 개수 배지와 빨간 점
- 이메일, SMS, 브라우저 푸시 알림
- 주문, 배송, 쿠폰, 이벤트 알림
- 문의와 답변 이외의 상태 변경 알림
- 기존 문의에 대한 일괄 알림 생성

## 3. 정보 구조와 경로

- 1:1 문의의 기준 저장소는 `inquiries` 컬렉션으로 유지한다.
- 상품 문의와 공개 QnA의 기준 저장소는 `qna` 컬렉션으로 유지한다.
- 일반 고객의 종 아이콘은 `/cs/inquiry?tab=list`로 이동한다.
- 관리자 종 아이콘은 `/admin/inquiries?filter=unread`로 이동한다.
- 마이페이지의 `문의관리` 링크는 `/cs/inquiry?tab=list`로 변경한다.
- 기존 `/mypage/qa`는 `/cs/inquiry?tab=list`로 리다이렉트해 중복 UI와 데이터 혼동을 제거한다.
- 관리자 공통 내비게이션에 `/admin/inquiries`의 `1:1 문의 관리` 링크를 추가한다.

## 4. 데이터 모델

`Inquiry`와 신규 `inquiries` 문서에 다음 필드를 추가한다.

```ts
unreadForAdmin: boolean;
unreadForCustomer: boolean;
```

### 생성 상태

고객이 새 문의를 등록할 때 다음 값을 강제한다.

```ts
unreadForAdmin: true;
unreadForCustomer: false;
```

### 관리자 확인 상태

- 관리자가 알림을 통해 문의 화면에 진입하고 새 문의 목록 로드가 성공하면 대상 문의의 `unreadForAdmin`을 `false`로 변경한다.
- 알림이 여러 건이면 화면에 표시할 문의 목록을 먼저 확보한 뒤 해당 문의를 일괄 읽음 처리한다.
- 관리자 답변 저장 시에도 `unreadForAdmin`을 `false`로 유지한다.

### 고객 확인 상태

- 관리자가 답변을 새로 등록하거나 기존 답변을 수정하면 `unreadForCustomer`를 `true`로 변경한다.
- 고객이 알림을 통해 문의 내역에 진입하고 답변 문의 목록 로드가 성공하면 대상 문의의 `unreadForCustomer`를 `false`로 변경한다.
- 알림이 여러 건이면 새 답변 문의를 먼저 화면에 유지한 뒤 해당 문의를 일괄 읽음 처리한다.

### 기존 문서 호환

- 두 필드가 없는 기존 문의는 읽은 상태로 취급한다.
- 기능 적용 이후 생성된 문의와 적용 이후 새로 작성·수정된 답변부터 알림을 발생시킨다.
- 기존 문의에 답변을 새로 등록하거나 수정하면 그 시점에 `unreadForCustomer: true`를 기록한다.

## 5. 실시간 알림 조회

알림 서비스는 문의 CRUD와 헤더 표현을 분리하는 단일 책임 모듈로 둔다.

- 일반 고객은 `userId == 현재 uid`와 `unreadForCustomer == true` 조건을 실시간 구독한다.
- 엄격 관리자는 `unreadForAdmin == true` 조건을 실시간 구독한다.
- 헤더는 개수가 아니라 읽지 않은 문서의 존재 여부만 사용한다.
- 구독은 최초 한 건만 확인할 수 있도록 제한해 헤더 비용을 낮춘다.
- 로그아웃, 계정 전환, 관리자 판정 변경, 컴포넌트 언마운트 시 기존 구독을 즉시 해제한다.
- 조회 오류가 발생하면 잘못된 알림을 표시하지 않고 종 아이콘을 숨긴다.

필요한 복합 인덱스는 고객 알림 조회를 위한 `inquiries(userId ASC, unreadForCustomer ASC)`다. 정렬을 추가하는 경우에만 정렬 필드를 같은 인덱스에 포함한다.

## 6. 헤더 UI

### 데스크톱

- 로그인 사용자에게 읽지 않은 알림이 있을 때만 `마이페이지` 오른쪽에 종 아이콘 링크를 표시한다.
- 관리자 계정에서는 같은 종 아이콘이 신규 고객 문의를 의미하고 `/admin/inquiries?filter=unread`로 이동한다.
- 관리자 링크가 함께 표시되는 경우 순서는 `마이페이지 → 종 아이콘 → 관리자`로 유지한다.
- 종 아이콘에 숫자, 점, 말풍선은 추가하지 않는다.
- 클릭 목표 영역은 최소 44×44px로 확보하되 기존 헤더 한 줄 높이와 간격을 유지한다.
- 신규 UI에는 box-shadow와 추가 border-radius를 사용하지 않는다.

### 모바일

- 모바일 메뉴 내부가 아니라 헤더의 메뉴 버튼 옆에 종 아이콘을 표시해 즉시 인지할 수 있게 한다.
- 알림이 없으면 아이콘과 해당 인터랙션 요소를 렌더링하지 않는다.
- 모바일 메뉴가 열린 상태에서 경로가 바뀌면 기존 헤더 규칙에 따라 메뉴와 disclosure 상태를 초기화한다.

### 접근성

- 일반 고객 종 아이콘의 접근 가능한 이름은 `새 문의 답변 확인`이다.
- 관리자 종 아이콘의 접근 가능한 이름은 `새 고객 문의 확인`이다.
- 아이콘 자체는 보조 기술에서 숨기고 링크의 접근 가능한 이름으로 의미를 전달한다.
- 링크는 키보드 포커스와 Enter 이동을 지원하고 최소 44px 목표 영역을 유지한다.
- 알림이 실시간으로 새로 나타날 때 시각적 토스트는 만들지 않고 화면 읽기 프로그램용 짧은 상태 메시지만 제공한다.

## 7. 목적지 화면 동작

### 관리자

- `filter=unread`로 진입하면 읽지 않은 문의 목록을 먼저 확보하고 화면에 표시한다.
- 목록 로드 성공 후 표시된 문의의 `unreadForAdmin`을 `false`로 일괄 변경한다.
- 읽음 처리로 Firestore 조건이 바뀌어도 현재 화면에서 확보한 문의는 갑자기 사라지지 않도록 진입 시점 결과를 로컬 상태에 유지한다.
- 답변 저장은 답변 객체, `status: answered`, `updatedAt`, `unreadForAdmin: false`, `unreadForCustomer: true`를 한 번의 원자적 업데이트로 반영한다.
- 답변 수정도 고객에게 새 답변 알림을 다시 발생시킨다.

### 일반 고객

- `tab=list`로 진입하면 문의 내역 탭을 초기 활성화한다.
- 읽지 않은 답변 문의가 있으면 해당 문의를 목록 상단에 유지하고 첫 항목을 자동으로 펼친다.
- 문의 목록과 답변 렌더링이 성공한 뒤 표시된 문의의 `unreadForCustomer`를 `false`로 일괄 변경한다.
- 읽음 처리 실패 시 문의 내용은 그대로 보여주고 알림 상태는 유지해 다음 구독에서 종 아이콘이 다시 나타나게 한다.

## 8. Firestore 권한

문의 생성 규칙은 기존 작성자 정보, 카테고리, 길이, 서버 시각 검증에 다음 조건을 추가한다.

- 생성 시 `unreadForAdmin == true`
- 생성 시 `unreadForCustomer == false`

고객 업데이트는 다음 변경만 허용한다.

- 활성 문의 작성자가 자신의 문서에서 `unreadForCustomer`를 `true`에서 `false`로 변경
- `unreadForAdmin`, 답변, 상태, 작성자, 본문, 생성·수정 시각 변경은 금지

엄격 관리자 업데이트는 기존 답변·상태 변경 규칙에 다음 조건을 추가한다.

- `unreadForAdmin`은 `true`에서 `false`로 변경 가능
- `unreadForCustomer: true`는 유효한 답변 추가 또는 답변 내용 수정과 같은 업데이트에서만 허용
- 답변 저장 시 `unreadForAdmin == false`
- 고객 알림만 임의로 생성하거나 작성자 데이터를 변경하는 업데이트는 거부

문의 읽기 권한과 hard delete 금지는 기존 정책을 유지한다.

## 9. 오류와 상태 처리

- 인증 또는 사용자 문서 확인 중에는 종 아이콘을 표시하지 않는다.
- 알림 구독 실패 시 헤더는 조용히 알림 없음 상태를 유지하고 개발 로그에 원인을 남긴다.
- 목적지 문의 목록 로드가 실패하면 읽음 쓰기를 실행하지 않고 기존 재시도 UI를 제공한다.
- 목록 로드는 성공했지만 읽음 쓰기가 실패하면 목록은 유지하고 종 아이콘이 다시 나타날 수 있게 한다.
- 관리자 답변 저장과 고객 알림 설정은 한 번의 Firestore 업데이트로 처리해 부분 성공을 방지한다.
- 일괄 읽음 처리는 Firestore 배치 제한을 넘지 않도록 조회된 문서를 안전한 단위로 나눌 수 있는 서비스 경계로 구현한다.

## 10. 테스트와 완료 기준

### 단위 테스트

- 문의 생성 데이터에 두 알림 필드의 초기값이 포함되는지 검증한다.
- 관리자 답변 추가·수정 시 고객 알림이 활성화되는지 검증한다.
- 관리자·고객 읽음 처리 서비스가 허용된 필드만 변경하는지 검증한다.
- 헤더가 일반 고객·관리자 역할과 알림 존재 여부에 따라 올바른 링크와 접근 가능한 이름을 렌더링하는지 검증한다.
- 로그아웃과 계정 전환 시 실시간 구독 해제가 호출되는지 검증한다.
- `/cs/inquiry?tab=list` 초기 탭, 새 답변 자동 펼침, 로드 성공 후 읽음 처리 순서를 검증한다.
- `/admin/inquiries?filter=unread` 진입 결과가 읽음 처리 후에도 현재 화면에 유지되는지 검증한다.
- `/mypage/qa` 리다이렉트와 관리자 내비게이션 링크를 검증한다.

### Firestore Rules Emulator

- 활성 고객의 정확한 문의 생성 스키마 허용
- 알림 초기값 위조 거부
- 작성자의 고객 알림 `true → false` 변경 허용
- 작성자의 관리자 알림·본문·답변·상태 변경 거부
- 엄격 관리자의 관리자 알림 읽음 처리 허용
- 유효한 답변과 고객 알림 활성화 허용
- 답변 변경 없는 고객 알림 임의 활성화 거부
- claim-only, role-only, inactive admin의 읽음·답변 변경 거부
- 다른 고객의 문의와 알림 조회·변경 거부

### 브라우저 흐름

1. 일반 고객이 1:1 문의를 등록한다.
2. 관리자 헤더에 종 아이콘이 실시간으로 나타난다.
3. 관리자가 종을 눌러 새 문의를 확인한다.
4. 관리자 종 아이콘이 사라진다.
5. 관리자가 답변을 등록한다.
6. 문의 작성자 헤더에 종 아이콘이 실시간으로 나타난다.
7. 고객이 종을 눌러 답변된 문의가 자동으로 펼쳐진 화면을 확인한다.
8. 고객 종 아이콘이 사라진다.
9. 다른 고객에게 문의와 알림이 노출되지 않는지 확인한다.
10. 데스크톱과 모바일에서 종 아이콘 위치, 44px 목표 영역, 키보드 이동을 확인한다.

### 품질 게이트

- 관련 Jest 테스트
- `npm run typecheck`
- 관련 파일 ESLint
- `npm run test:rules`
- `npm run build`
- 데스크톱·모바일 브라우저 확인

## 11. 예상 영향

- 고객과 관리자가 새 문의·새 답변을 별도 새로고침 없이 인지할 수 있다.
- 1:1 문의와 상품 QnA 경로가 분리되어 마이페이지의 잘못된 0건 표시 문제가 해소된다.
- 알림 문서 컬렉션이나 서버 트리거를 추가하지 않아 현재 요구에 필요한 수준으로 복잡도를 제한한다.
- 향후 주문·쿠폰 등 범용 알림이 필요해지면 별도 `notifications` 컬렉션으로 확장할 수 있지만 이번 구현에는 포함하지 않는다.
